# `editor`

- eframe/egui editor. Big modules are a parent file plus a same-named folder: see "Where the big files split" in `docs/architecture/crates.md`. Open one file under `docs/editor/` (the list is in `docs/architecture.md`). Play mode: `docs/architecture/play-mode.md` (kept Play edits: `play/kept.rs`; several clients, `play/multi.rs`: `Play` derefs to the shown device's `Session`, so route anything every device needs through `Play`'s own methods). Visual-debug overlays are editor-only (`viewport.rs`; Viewport > Overlays), as are Viewport > View Mode's debug views (`viewport/view_mode.rs`; render's `debug-views` feature). Welds, Attachments (stored relative to their part; the tools move them in world space via `constraints::localize`) and the Constraints overlay (joints too): `constraints.rs`. The Constraint tool (`app/constraint_tool.rs`; joints and movers, `constraints::takes_two_surfaces`) picks surfaces through `ViewportScene::constraint_pick` / `ViewportOutput::surface`, like a terrain brush takes the left button. Terrain Studio (including foliage): `docs/terrain.md`. Geometric snapping (Surfaces, Collisions, Join Surfaces, Snap Points; `docs/editor/transforms.md`): the `editor-tools` crate's `snapping.rs`, `snapping/points.rs`; the distance reading `viewport/move_overlay.rs`; the measuring grid `viewport/grid.rs`; the view cube: `viewport/view_cube.rs`.
- `app.rs` runs the frame. Panels in OS windows: `layout/floating.rs`, `app/floating.rs`. Color swatches and saved palettes (route new color buttons through `color_palette::edit_srgb`): the kit's `color_palette.rs`. The Material tool's library: `prototype.rs`, `app/custom_materials.rs`. Open and Play: `app/session.rs`. Selection, tools and undo: `app/edits.rs`. Insert, delete and reparent: `app/tree_ops.rs` (where a new part lands: `spawning.rs`). Menus and panels: `app/chrome.rs` (and `app/chrome/`); on macOS the menus are in the system menu bar, `app/native_menu.rs` (a new header menu item needs its twin there). Console commands: `app/commands.rs`. Files, import and export: `app/files.rs` (and `app/files/`); Build Game's files and `--build-game`: `build_game.rs` (the game's icons: `build_game/icons.rs`); Settings > This project > Branding: `app/branding.rs`. The Toolbox tab (online assets, `docs/editor/assets.md`): the `editor-toolbox` crate (`crate::toolbox_panel` here), its actions `app/toolbox.rs`. The Downloaded / Imported Assets tab: `asset_inventory.rs`, its actions `app/inventory.rs`; the Assets panel's grouping by source: `asset_browser/origin.rs`. Asset drops: `app/assets.rs` (a global asset is copied into the project first: `global_assets.rs`; route new uses through `EditorApp::use_global_asset`). Animation tab (follows the selected Animator; Animate is `EditorApp::animate`): `animation.rs` (and `animation/`); animated FBX import: `anim_import.rs`. UI Designer tab (artboard, rulers, anchors, palette, inspector, several selected; applied by `designer_actions` in `app/chrome/panes.rs` and `app/ui_selection.rs`): the `editor-ui-designer` crate (`crates/editor-ui-designer/src/`, imported by the editor as `ui_designer`) (`docs/ui.md`). Engine rebuild and relaunch (debug builds with the `engine-dev` feature, from the source tree only): `rebuild.rs`, `relaunch.rs`, `app/engine.rs`; scripts keep their state when saved in Play (`blocks::hot_reload`, enabled in `play.rs`) (`docs/editor/scripts.md`). Profiler panel: `profiler.rs` (fed by `Session::cost`, `Session::memory` and the viewport). Debug > Graphics Benchmark (editor graphics settings only; its own renderer and in-memory worlds, `docs/rendering/settings.md`): the `editor-benchmark` crate (`crate::graphics_benchmark` here), its actions `app/graphics_benchmark.rs`. Asset Check panel: `asset_check.rs`, its scan and fixes in `app/asset_fixes.rs` (`project::check_assets`, `project::plan_fix`; editor-only). Input window (File > Input…, `input.json`): `app/input_settings.rs`; the ribbon's Controls menu: `app/controls_ui.rs`; Play's mouse and touch input from the viewport: `viewport/game_input.rs`. Tags panel: `tags.rs`, its actions `app/tags.rs`; Sequencer tab (Phase 51; timeline, dope sheet and curves reused from `animation/`, Scene view preview): `sequencer.rs`, its actions `app/sequencer.rs` (`docs/project/sequences.md`); Tests panel (Phase 53): `game_tests.rs` (runs on a thread through `axcenity_testing::Runner`), its actions `app/game_tests.rs`; spec tabs save as plain files in `write_tab` (`docs/project/game-tests.md`); Levels panel (Phase 48): `levels.rs`, its actions `app/levels.rs` (the open level is `OpenProject::level`; opening one goes through `Discard::OpenLevel`); attribute and tag edits go through `EditorApp::annotate` (`History::record_annotations`). Lua plugins (Phase 54; `docs/editor/plugins.md`): `plugins.rs` (state, Plugins panel), `app/plugins.rs` (calls, dock tabs, ribbon), their undo `history/edits.rs`. Model Studio tab (Phase 55; `docs/editor/model-studio.md`): the `editor-model-studio` crate (`crate::model_studio` here; own undo while hovered: modeling tools and the adjust panel `tools.rs`, proportional editing and pivots `proportional.rs`, the Modifiers panel `modifiers.rs`, the UV menu and UV editor pane `uv_editor.rs`, Paint mode `paint.rs`; Rig, Weights and Pose mode `rig.rs`, drawn through `View::use_model`), its open, save and bake `app/model_studio.rs`. Character Studio tab (facial animation F6; `docs/editor/character-studio.md`): `character_studio.rs` (and `character_studio/`: Rig, Expressions, Lip sync), its saves and edits `app/character_studio.rs`. The Character Studio workspace (no project, in place of the start screen; CS2): `character_workspace.rs` (and `character_workspace/`: `ui.rs`, `stage.rs`), opened and left by `app/character_workspace.rs`, its start page `start/characters.rs`. Universal search (Ctrl+K; the command palette and Quick Open are views of it; `docs/editor/shell.md`): the window `command_palette.rs`, the index and its providers `app/search.rs` (make a new system searchable with a `SearchProvider`, stamped so it's listed again only when it changes), the commands `app/command_palette.rs` (a new menu item or ribbon button needs a `Command`; `every_ribbon_and_menu_command_can_be_run_from_the_palette` checks); Find in Scripts `find_in_scripts.rs` and `app/find_in_scripts.rs`; code-tab completion and signature hints (G4) `script_completion.rs`, drawn by `scripts/assist.rs`; luau-lsp errors `luau_check.rs`, run per tab by `app/luau_checks.rs` (the shipped or downloaded luau-lsp: `luau_lsp.rs`); Find References, Unused and Rename or Move… `app/asset_refs.rs`. Version History, checkpoints, restores and Back Up Project (Phase 72): `app/version_history.rs` (a restore refuses unsaved changes). Splines (Phase 73; `docs/architecture/splines.md`): drawing and hit tests `splines.rs`, point editing `viewport/input.rs` (`spline_input`, `ViewportOutput::spline`), edits and Insert `app/splines.rs`; SplineMeshes and SplineScatters (Phase 74): `app/spline_content.rs` (`generate_frame` each frame and after undo, Insert, Assets picks, Bake, Flatten Terrain Along). MCP server for AI clients (`--mcp`; `docs/editor/mcp.md`): `app/mcp.rs` and one file per tool in `app/mcp/`; every AI write goes through `app/mcp/ops.rs::write` (one undo step, rollback on failure); clients in the open editor (Settings > AI connections, listener, relay, drained in `ai_frame`): `app/mcp/live.rs`. Version Explorer (Help; `docs/editor/shell.md`): `version_explorer.rs`, reading `releases/` that `build.rs` embeds; update checks, Settings > Updates and the update chip: `app/updates.rs` (official builds only; never in tests); downloading and installing updates: `app/update_install.rs`. Opening an older or newer project ("Upgrade this project?", refusals): `app/project_upgrade.rs`. Start screen Team Projects page: `start/team.rs`. Start screen Learn, Documentation and the API Reference's examples (pages are `documentation/`): `start/docs.rs`, `start/learn.rs`, `start/reference.rs` (`docs/editor/learn-and-docs.md`).
- Route edit-mode world changes through `EditorApp::change` so undo/history stays consistent (in a Collaborate session (`--collab-host`, `--collab-join <link>` or a bare invite link; old `--team-*` flags still work) (panel and title bar chip: `app/team_panel.rs`; setup wizard and Start Session dialog: `app/collab_setup.rs`, `docs/research/collaborate.md` §5.4; script and stylesheet tabs typed in together through live documents, never locked: `team_live_docs`, §4.1; chat `app/team_chat.rs`, the Team Board (shared tasks in `team/board/`, the `teamwork` crate; `docs/editor/team-board.md`) `team_board.rs` and `app/team_board.rs`, History (checkpoints, restores) `app/team_history.rs`, the Owner's Audit log `app/team_audit.rs`; the project's Git remote and automatic checkpoints (Collaborate 2.0, `docs/research/collaborate-persistent.md`) `app/collab_repo.rs`, its conflicts (`conflicts`, `resolve`) `app/collab_conflicts.rs`, the panel's Project section and the Repository, History and Resolve windows `app/collab_repo_ui.rs`, the project ID, project records, rejoin and hosting for members `app/collab_project.rs`, the session going on when its host leaves or is lost `app/collab_handoff.rs`, who gets in, where a host listens and the Someone wants to join window `app/collab_trust.rs` and others' cursors in script tabs `scripts/others.rs`, §5.7; others' selections reach the viewport, Explorer and Properties through `EditorApp::team_selections`), `app/team.rs` sends whatever changed the edit World each frame from its edit journal, so tools need no code of their own, and keeps the session's files in step through `collab::Mirror` (a joiner's folder opens as the project: `open_team_mirror`); content the editor makes for itself goes inside `World::unrecorded`); Play edits target the session world and are discarded on Stop. Clip, controller and prefab create, rename, duplicate and delete go through `History::record_asset` (a missing file is `None`). Prefab copies' Apply, Revert, Unpack and New variant: `app/prefabs.rs` and `prefab_menu.rs`, one `History::record_world_and_files` step each.
- The shared UI base (`theme`, `widgets`, `responsive`, `color_palette`, `lua_syntax`, `wheel`, `screen`, `snapshot`) is the `editor-kit` crate, re-exported at this crate's root, as are panel families moved into crates (G11: `editor-toolbox`, `editor-benchmark`, `editor-model-studio`, `editor-node-graph`, `editor-ui-designer` with `style_panel` and `ui_handles`) and what they share with the editor (`editor-tools`: `gizmo`, `snapping`, `shortcuts`, `tree`, `props`, Animation's `posing` and `preview`, and the `Edit`, `Field`, asset-tile, selection and animatable types re-exported where they were); `theme.rs` here adds the editor's own icons. Colours come from `theme::palette(ctx)` tokens and controls from `widgets`; don't hardcode chrome colours. Panels must fit a 260-point column: use `responsive` (`toolbar`, `form`, `split`) instead of fixed-width rows. Drawing tests need `theme::test_context()`. Don't call egui `Context`/`Response` methods inside an `input` closure; keep eframe, egui and render on compatible wgpu majors.
- Drawing tests save PNGs of what they draw when `AXCENITY_SNAPSHOTS` names a folder (the kit's `snapshot.rs`); look at them after UI changes.
- The generic node-graph editor is the `editor-node-graph` crate (`crate::node_graph` here); the UI Designer's Event Graph tab and Live Preview are `editor-ui-designer/src/event_graph.rs`, graph documents, saving and their undo `app/ui_graphs.rs` (`docs/scripting/ui-graphs.md`). The Behavior Tree tab is `behavior_tree.rs` (documents, undo, drawing) and `app/behavior_trees.rs` (`docs/architecture/navigation.md`); the Dialogue tab, the same shape, is `dialogue_editor.rs` and `app/dialogues.rs` (`docs/scripting/api-dialogue.md`). The Data Table tab is `data_table.rs` and `app/data_tables.rs`; its edits go to `Assets` through `hand_over_tables` (`docs/project/data-tables.md`). The Material tab is `material_editor.rs` (its Graph view and Parameters `material_editor/graph.rs`) and `app/material_tab.rs`; its edits go to `Assets` through `hand_over_materials` (`docs/editor/assets.md`). Material graphs' nodes and their compiler to WGSL are `material_graph.rs` (editor-only: the player reads the WGSL; `docs/rendering/models.md`).
- egui fills only convex shapes: `block_editor.rs` fills blocks as convex pieces and outlines them as one path. The Graph view of block scripts is `block_editor/graph.rs` (`docs/scripting/graphs.md`). Block scripts' undo (both views, Ctrl+Z over their tab): `app/block_undo.rs`.
