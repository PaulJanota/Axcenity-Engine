# Editor shell

The window, ribbon, panels, camera, and visual design. The other editor pages are listed in `docs/architecture.md`.

- Built on **eframe 0.36** (egui's app shell) with its wgpu backend. eframe owns the window, event loop and GPU device; it must stay on the same wgpu major as `render` (0.36 ↔ wgpu 30, winit 0.30), so upgrade them together, with glyphon, egui_dock and egui-phosphor (versions in the workspace `Cargo.toml`).
- Layout like Roblox Studio: menu bar on top, **Explorer** down the right side, the **Console** along the bottom under the viewport, viewport in the middle.
- **Dockable panels** (added on request after Phase 37; `layout.rs`, `egui_dock` 0.17): Scene View (the viewport), Explorer, Properties, Console, Assets, Animation, UI Designer (see `docs/ui.md`), Terrain, Profiler and Mixer (see `docs/architecture/play-mode.md`), Asset Check (see `docs/editor/assets.md`), LOD Inspector (see Levels of detail in `docs/rendering/performance.md`) and each open script (see `docs/editor/scripts.md`) are each a tab in a docking area, like Unity. Drag a tab onto another panel's tab bar to join it, onto a side of a panel to split it, or anywhere else to float it. The Scene View can be moved and closed but not floated. **Welcome page** (cohesion pass CP2; `Pane::Welcome`, `app/welcome.rs`): whenever no document tab is open (the Scene, a script or block script, Behavior Tree, Dialogue, Data Table, Material, Sequencer or Model Studio; Animation and the UI Designer follow the selection, so they don't count), the documents' place shows a Welcome tab, like Visual Studio's start page: the Axcenity mark as a faint watermark, the project's name, Start (Show the Scene View, New script, Search everything, Open another project…), Recent tabs (the scripts closed last in this project, 8 per project, saved between runs under "recent tabs"), Recent projects (the 5 others opened last; opening one asks about unsaved changes first) and the Shortcuts worth knowing, from the shortcut table. Closing the Scene puts it in the Scene's own place (`Layout::close_scene`); opening any document takes its place and it goes (`Layout::keep_a_document`, each frame); it can't be closed, toggled or floated. View > Show Scene, the ribbon's Show Scene and Play bring the Scene back where the page was, or beside the open documents. A saved layout with the Scene closed loads as it was. The others close with their ×, and View > Panels (or the Home tab's Panels group) shows or hides them; Reset Layout puts everything back. A closed panel opens again next to the panel it starts beside. The layout is saved between runs (eframe storage, JSON); a damaged one gives the starting layout. **Layouts** (design system V17, `layout/presets.rs`, `app/layouts.rs`): View > Layout switches to Default (the starting layout, which Reset Layout also gives) or a preset for a task (Scripting, Animation, UI Design, Modeling & Assets, Lighting & Environment), or to a layout saved with **Save Current Layout…** (a name; a preset's name is refused; the same name replaces it). Saved layouts are `Layout::to_text` snapshots under the `saved layouts` key. Switching keeps open scripts and plugin tabs (they come back beside the Scene) and never touches the selection; the command palette lists every layout and Save Current Layout….
- **Floating panels** (`layout/floating.rs`, drawn by `app/floating.rs`): a floated panel is a real OS window (an immediate egui viewport with its own dock area), so it can go anywhere, on any monitor. It has no OS frame: empty space in its row of tabs moves it (double-click maximizes), the right end of that row has **Dock Back** and **×**, and its edges resize it (`window_frame::panel_title_area`, `panel_buttons`, `edges`). On macOS the traffic lights stay, with a slim strip above the tabs and Dock Back in it. **Dock Back** puts each panel back where it was docked: among the tabs it left, at its old place, or split off the panel beside it on the same side at the same size (`Layout::remember_homes`, noted each frame before the main dock is drawn, since a dragged tab has already left by the time it's seen; saved with the layout; if what it was beside has gone, it goes where it starts out). **×** closes the window's panels (View > Panels opens them again), except scripts and plugin tabs, which dock, as a script may hold unsaved changes. **Several tabs in one window**: drag a tab out of the main window or another window and let go over a window (it's outlined in the accent colour) to join its tabs (`update_following`, `merge_windows`), or use the tab's right-click **Move to … Window**; inside a window tabs group and split as in the main dock. egui_dock's floating surfaces are turned into windows the frame they appear (`Layout::absorb_floating`); a tab dragged past the edge of its window tears off at once and follows the mouse until let go (`tear_off`, `update_following`; the source window keeps the mouse's events, so it reports where the mouse is, in physical pixels so monitors of different scale work). Tearing off starts egui_dock's drag memory afresh (`Layout::dock_generation`, part of every dock area's id), as it would otherwise look for the tab at its old index and panic; each panel draws in a `Ui` whose id depends only on the panel (`in_panel_memory`), so its scroll position and open sections move with it. egui_dock doesn't say which tab is dragged, so `dragged_tab` rebuilds its tab ids (test `a_tab_dragged_past_the_edge_of_the_window_is_torn_off` catches it if that changes). A tab's right-click menu has Float in New Window and, in a window, Dock in Main Window; letting go of a tab torn out of a window over the main one docks it. Panels draw from the app's state, so they keep what they showed; the keyboard shortcuts go to the window with focus. Windows and their places are saved with the layout (`SavedLayout`; an older layout, just the dock, still loads); Reset Layout brings them all home, also the way back if a saved window was on a monitor that's gone. Assets can't yet be dragged from a window into the Scene (egui's drag payloads don't cross viewports): double-click a tile instead. Don't call `Context` methods inside an `input` closure here: background threads take its write lock, and it deadlocks.
- **Ribbon tabs** (`ribbon_tabs.rs`): **Home** is Play, Run and Stop, Select / Move / Resize / Rotate / Transform, Snapping (the move and rotate steps, Surfaces, Collisions, Join Surfaces and Collision Groups…; see `docs/editor/transforms.md`), the six part shapes, and **Panels** (Explorer and Properties, and a **Panels ▾** menu of every panel with Reset Layout; moved here from the View tab on request). Clicking the picked tool's button, or pressing its key, again goes back to Select. **Model** (reorganized on request) is the build tools (Paint, Material, Anchor, Lighting, Emission, Angular), Phase 50's **Solid Modeling** (Union, Negate, Intersect, Separate; `app/solid.rs`, `docs/architecture/solid-modeling.md`), Constraints and Import. **World** (the old World, Gameplay and Terrain tabs merged on request; a saved Gameplay or Terrain tab opens it) is a few dropdowns, not a button per class (`app/chrome/ribbon_menus.rs`; each item keeps its tooltip, `insert_hint`, and the Explorer's right-click Insert menu still has every class): **Lights & Sky** (Light ▾: lights, probes and Bake Probes; Sky ▾: Atmosphere, Clouds, weather, outlines, color correction), **Effects** (Sound ▾, Particles, Post FX ▾: lens effects, Graphics Volumes and their effects), **Gameplay** (Character ▾: characters, humanoids, controllers, health, damage zones, tools, inventories, agents; Interact ▾: prompts, click detectors, seats; Spawn ▾: spawns, teams, checkpoints, cameras; Vehicle ▾) and **Terrain** (the Terrain Studio, and Brush ▾ for its tools). **UI** is Screen, Layout ▾, Elements ▾ and Controls. **Collision Groups** (Phase 38, `app/collision_groups.rs`; its button is in Home's Snapping group) is a window that adds groups by name, removes them with × (not Default; their parts then collide as Default), and has a lower-triangle matrix of checkboxes, ticked where two groups collide; each change writes `collision-groups.json` at once and is one undo step (undo writes the file back and the world reads it again, `EditorApp::reload_project_settings`), and is disabled during Play. Model's **Constraints** (Phase 35: **Weld** welds the selected parts, and the parts in selected Models, to the largest of them by volume, with a `WeldConstraint` (Part0 the largest, Part1 the other) inside each other part, as one undo step "Weld N parts", off with fewer than two parts; **Attachment**; and, Phase 36, **Constraint** (`app/constraint_tool.rs`), whose menu picks a joint: then the left button picks part surfaces instead of selecting (marked with a ring, and a line from the first to the mouse), a click on one part then on another makes an Attachment at each point, both with their X axis out of the first surface, and the joint in the first part, as one undo step "Insert <class>", a spring's FreeLength and a rope's or rod's Length set to the distance; the tool stays on until Stop in its menu, Esc or Play; Phase 37: the menu's second group is the movers: LinearVelocity, AngularVelocity, VectorForce and Torque take one click, making an Attachment there (X out of the surface) and the mover in that part, and AlignPosition and AlignOrientation take a second click on the part they follow, making its Attachment1 too (TwoAttachment, their default Mode), each as one undo step "Insert <class>"), and Import. **UI**, **Script** and **Test** (Play/Stop, **Clients**, and Check Assets; Clients is how many clients Play runs, the Network window with latency, jitter and packet loss, and, while several play, which device the viewport shows: moved here on request from beside Play and Stop on every tab; then the **View** group, from the View tab merged into Test on request, a saved View tab opens Test: View Cube, **Grid** (the measuring grid, `docs/editor/transforms.md`), **Overlays ▾** (colliders, raycasts, bounds, emitters, nav mesh, agent paths, constraints, contacts, bodies, streaming, light probes, culling, skeletons, then Light Cones; Streaming: `docs/architecture/streaming.md`; Light Probes: `docs/rendering/sky.md`; Skeletons: `docs/rendering/animation.md`) and **View Mode ▾**; **Constraints** (Phase 35, `constraints.rs`) draws each WeldConstraint as a line between its parts' middles, light blue or grey when disabled, and every Attachment as a ring with its X (red) and Y (green) axes; a selected Attachment shows that way with the overlay off too; Phase 36: each joint is an orange line between its attachments (a zigzag for a spring), with the axis through Attachment0 for a hinge, prismatic or cylindrical constraint and a yellow arc between a hinge's limits, grey when disabled, and a selected joint shows with the overlay off; Phase 37: each mover is green from Attachment0: an arrow along a LinearVelocity's VectorVelocity or a VectorForce's Force, its axis and a circling arrow for an AngularVelocity or Torque (all in their RelativeTo axes), a line to an AlignPosition's target with a cross there, and a line to an AlignOrientation's Attachment1 with arrows along the X and Y axes it turns to, grey when disabled) are their own tabs. The tab row is centred, on the app background like the header, and so are the ribbon's groups under it unless Settings > Appearance > **Ribbon** is Left (`theme::RibbonAlign`, default Centered; the groups' width is remembered per tab from the frame before and the first frame of a tab is redrawn; when they don't fit they start at the left and scroll; test `the_ribbon_centres_its_groups_when_asked`); the ribbon under it is a shade lighter (the panel colour) with a hairline above and below, and the active tab is filled with that shade and outlined so it joins the ribbon, and each built-in tab has an icon before its name (house, cube, globe, layout, code, flask, puzzle piece); custom tabs have a star. **Custom tabs**: + after the tabs (or View > New Ribbon Tab…) makes a tab from any groups, in any order; right-click one to edit or delete it. Custom tabs and the tab showing are saved between runs. Every tab keeps the height of the tallest one seen (Home, for its Snapping grid), so the panels under the ribbon don't jump when tabs change (test `the_ribbon_keeps_one_height_across_tabs`).
- **Viewport**: `render::TextureRenderer` draws into a texture sized in physical pixels, registered with egui as a native texture and re-pointed after each resize. Only redraws when egui does (input or a requested repaint), so an idle editor uses no GPU.
- **Steady frames** (`EditorApp::keep_frames_steady`; fixed on request): drawing only on input turned small back-and-forth mouse movements into bursts of frames with gaps, and on a variable refresh rate display (FreeSync, G-Sync; Windows also puts windowed apps on VRR) the refresh rate swung with them, which OLED and VA panels show as the screen briefly brightening, worse in a window. So for a second after any input (`STEADY_FRAME_SECONDS`) frames keep coming at the display's rate; then the editor is idle again. A frame with no input after more than `WAKE_GAP_SECONDS` of idling (a watched file changed, a background job finished) counts as input, the loading screen draws every frame instead of at the pace files are read, and toasts draw at the display's rate. Steady frames are also presented on a fixed grid (`EditorApp::pace_frame`, `next_present`; **Steady frame rate** in Settings > Accessibility, 60 a second by default, or the display's own rate for no limit), because frames that come as fast as each is ready still vary in length with the work in them, and the panel follows every one; a frame that misses its point takes the next, so the grid holds. **Hold the refresh rate steady** (off by default) keeps drawing, at that rate, while the window has focus, for panels that react to the rate dropping when the editor goes idle; it gives up the idle editor's zero GPU use. The start screen does the same while it shows, because its backdrop is always moving: frames keep coming on the grid while the window has focus, and stop in the background or with Reduce motion. Screen captures don't show the flicker (the frames themselves don't change: rendering the same scene repeatedly gives identical pixels on every preset), only the panel does. Tests: `frames_keep_coming_for_a_second_after_input_then_stop`, `holding_the_refresh_rate_draws_only_while_the_window_has_focus`, `the_start_screen_keeps_drawing_while_focused_unless_motion_is_reduced`, `steady_frames_are_presented_on_a_fixed_grid`. Scenery that moves on its own (swaying plants, drifting clouds, moving surface shaders) asks for frames at `SCENERY_FPS` (30) rather than the display's rate, so an idle editor showing Abandoned Farmhouse no longer keeps the GPU busy; any input brings full-rate frames back.
- **Camera** (Studio-style): right-drag looks (cursor hidden; `Locked` on macOS, `Confined` elsewhere), WASD/E/Q fly while the mouse is over the viewport, Shift slows, wheel zooms toward the focus point, middle-drag pans, Alt+left-drag orbits the focus point. Keys are read by physical position, like the player.
- **Fly speed** (added to Phase 8 on request): Shift+wheel, or the wheel while right-dragging (like Unity and Godot), changes the WASD speed by 20% per notch, from 1 to 500 studs/s (default 20). A pop-up in the middle of the viewport shows the new speed for a second, then fades. The speed survives opening another project but isn't saved between sessions. The player keeps a fixed 20 studs/s.
- **Explorer**: shows the real root (`Game`, class `DataModel`; `game` in scripts) and every Instance under it. `game` and `Workspace` start open, everything else closed. The class is shown next to names that differ from it. **Filter**, at the top, shows only the Instances whose name or class has what's typed in it (case and spaces ignored), with every branch above them open and dimmed; the arrows do nothing while filtering, and clearing it puts the branches back as they were. Shift-click selects the range among the rows shown (`Explorer::filter`, `add_matching_rows`; tests `the_filter_shows_what_matches_and_the_branches_above_it`, `clicking_an_arrow_while_filtering_leaves_the_branches_alone`). The row list is kept between frames and built again only when the tree, the child order or the open branches change (every frame while filtering); names are read live. Only the rows on screen are drawn (`ScrollArea::show_rows`), so 10,000 rows cost what 100 do, and revealing a selection scrolls straight to its row (tests `only_rows_on_screen_are_drawn_and_reveal_scrolls_to_any_row`, `rows_are_kept_until_the_tree_or_the_open_branches_change`).
- **Console** (v3 Phase 2; `output.rs` for the log, `console.rs` for the command line, `app/commands.rs` for what commands do; it replaced the Output panel, and layouts saved with `Output` still load): the log is editor messages (project opened, with object and script counts) and load errors, one line each with the full cause chain (file and line for bad JSON), filtered by severity. A failed open keeps the current project. During Play, script output and errors join it. The log keeps the newest 10,000 lines (`Output::MAX_LINES`, dropped 1,000 at a time); a note at the top says how many older lines were dropped. Counts per severity are kept as lines arrive, and only the lines on screen are drawn, from heights worked out once per line and width, so a chatty script doesn't slow the editor (tests in `output.rs`'s `bounded_tests`). Under the log is a command line; each command is echoed (a `>` line) before what it printed. The command line grows with what's typed up to a third of the panel's height, then scrolls (`Console::room`), and its completions list shows three rows at most and scrolls, so a short Console never runs its input or completions over the log (cohesion pass CP2).
  - **Built-ins**: `help`, `clear`, `select <name|path>` (a dotted path from `game`, `workspace` or a service, such as `Workspace.Model.Door`, or a name searched everywhere), `find <name>` (lists and selects every Instance whose name contains it, ignoring case), `open <script>` (by its Instance's name or its path), `play`, `run` (Run without a player), `stop`, `save` and `check` (scans the project; see `docs/editor/assets.md`). A built-in is the first word with nothing after it that makes it Lua, so `clear = 5` and `select(2, ...)` are Lua.
  - **Lua**: anything else, with the same sandbox as scripts (`script::run_edit_command`, `ScriptRuntime::run_command`). A command is first tried as an expression, so `workspace.Baseplate.Size` prints its value. Outside Play it runs on the server side in a throwaway interpreter against a copy of the edit world; if it changed anything, the copy becomes the world and the old world is kept as one undo step, "Console: <command>" (`History::record_world`). During Play it runs on the game's server side as a coroutine (so `task.wait` works), commands share globals, and changes are lost at Stop like any Play change. Errors read `console:1: ...`. A line that isn't valid Lua and starts with a plain word (`teleport Pad`) is reported as an unknown command, with the Lua error after it; so is a lone word that isn't a global, outside Play.
  - **Keys**: Enter runs, Shift+Enter starts a new line, Up and Down walk the history while the input is one line (the last 200 commands, saved between runs), and Tab completes built-ins (as the first word), global names, and after a dot the children (with names Lua can write that way) and properties of the Instance the path names. With several matches Tab fills in what they share and lists them above the input.
- **File menu** (`app/chrome/menus.rs`, unified Phase 5): grouped under quiet headings. **Project**: New Project… (asks to save, closes the project and opens the start screen's New Project dialog), Open Project…, Save, Version History…, Save Checkpoint…, Back Up Project, Close Project (version history, checkpoints and backups: `app/version_history.rs`, `docs/project/export.md`). **Import**: Import… (see `docs/editor/import.md`). **Publish**: **Build Game ▸** (Export Game before Phase 5): For this OS, For Windows, For macOS, For Linux, and Show splash in built games (see `docs/project/export.md`). Then Open Stylesheet…, New Stylesheet, Check Assets, Set Up VS Code Autocomplete, Settings… and Quit.
- **Universal search** (Ctrl+K, Cmd+K on macOS, or Edit > Search Everything…; `command_palette.rs` for the window and ranking, `app/search.rs` for the index and providers, `app/command_palette.rs` for the commands): one list over the whole editor, each row tagged with a category: **Commands** (every menu and ribbon command and plugin toolbar button), **Tools** (the transform and build tools, Terrain Studio and its brushes, Model Studio, the Constraint tool, the ribbon tabs, and the editor panels that are tools: Animation, UI Designer, Terrain, Material and the rest of `search::TOOL_PANES`), **Objects** (every Instance in the world shown, the session's during Play; detail is its class and full path), **Assets** (the Assets panel's files and the global assets the project hasn't got, with their kind), **Scripts**, **Levels**, **Settings** (rows of the Settings window, `settings::SEARCHABLE`) and **Properties** (of the last selected object). Chips under the field show how many rows match in each category; clicking one, or Tab and Shift+Tab, narrows the list to it. A query starting with `>` searches only commands and tools. Under the list, the highlighted row says what it does (or, dimmed, why it can't run now).
  - **Ranking**: a fuzzy match (every letter in order; word starts, runs and the start score more; ASCII text is matched without copying) on the row's title and aliases, then, scoring less, on where it lives and its title together, then (queries of three letters or more) on its description's words. A name that is the query scores most (more again when the case matches), one that starts with it some. Commands' aliases include what the menu item or button says and synonyms (`search::synonyms`: Delete is found by "remove", Build Game by "export" or "package", Settings by "preferences"); every command has a description (`search::command_description`, reusing the ribbon's hover words where there are some; `synonyms_and_descriptions_find_commands_and_tools` checks none is missing). Commands and tools score a little more than settings, scripts, assets and levels, and those more than objects and properties, which are far more numerous. With nothing typed, the last 20 rows run or opened lead (saved between runs), then commands, tools, settings, scripts, levels, assets, properties and objects in order. The ranking is kept until the query, the chip, the recent list or the index changes, so it isn't redone every frame.
  - **Index** (`search::SearchIndex`): one bucket of rows per `SearchProvider`. Each provider gives a stamp, a number that stays the same while what it would list does; the index lists a provider again only when its stamp changes (checked each frame while the window is open, so a change during Play shows at once), and providers without one (commands, whose enabled state changes with the editor's, and levels, read from disk) when the window opens. Objects' stamp is the world's `structure_version` (creating, deleting, moving) and the sum of every Instance's `revision_without_motion` (renaming, and nothing else that's searched; revisions only go up, so the sum changes whenever one does); assets' is `AssetBrowser::generation`, which goes up only when a scan (every two seconds, or at once after the file watcher's note) finds something new, renamed or gone, so the files aren't walked a second time; scripts' is a hash of their paths; properties' the selection and its revision. Rows point at what they open by `SearchTarget`: a `Command` (the one command registry), an Instance by its `InstanceId`, a file by its path, a Settings page and row, or a property. Typing ranks again but lists nothing again (`typing_ranks_again_but_lists_nothing_again`); creating, renaming, moving and deleting objects and adding or removing asset files show at the next refresh (`the_index_follows_creating_renaming_and_deleting_objects`, `assets_show_up_and_go_as_files_come_and_go`). A new editor system makes itself searchable by adding a provider in `SearchIndex::new` (or `SearchIndex::register`), nothing else; plugin toolbar buttons already are.
  - **What a row does**: a command runs as its menu item or button does (`EditorApp::run_command`). A script opens its tab; a material opens the Material tab and a data table the Data Table tab; any other asset shows in the Assets panel (every category, searched for its path, picked; `AssetBrowser::reveal`); a level opens (asking to save first); an object is selected and shown in the Explorer. A setting opens Settings on its page, scrolls to the row and outlines it in the accent for two seconds (`settings::find_setting`; `every_searchable_setting_is_found_on_its_page` checks each listed row is drawn on its page). A property selects its object if it isn't, opens Properties and types the property's name into its filter (`properties::set_filter`).
  - **Cost** (release, cloud container, `search_cost_at_100_1000_and_10000_objects`): see the numbers in `docs/research/usability/verification.md`, Universal search.
- **Command palette** and **Quick Open** (unified Phase 70) are views of universal search: Ctrl+Shift+P (Cmd+Shift+P on macOS), or Edit > Command Palette, opens it with `>` typed (commands and tools; a backspace searches everything), and Ctrl+P, or Edit > Quick Open…, opens it on everything. Every command is a `Command` run by `EditorApp::run_command` the way its menu item or button runs it: a new menu item or ribbon button needs one too, and `every_ribbon_and_menu_command_can_be_run_from_the_palette` opens every menu, submenu, ribbon tab and dropdown and fails on a label the palette hasn't got. The Clients group's values (how many clients, the Network menu's latency, jitter and loss) aren't commands.
- **Opening projects**: `axcenity-editor <folder>` or File > Open Project… (`rfd` native folder dialog; the desktop portal on Linux). With no folder, the editor starts empty with a hint in Output.
- **Loading screen** (`loading.rs`): opening from the start screen, File > Open Project or the command line reads the project on a background thread, so the window never freezes. The thread reads the project's files (`project::load_with_progress` reports the manifest, any upgrade, `world.json`, each terrain and each script), then loads every model and texture the Workspace draws (`scene::asset_files`, all requested at once so the asset loading workers read them in parallel, the screen naming the first not yet in), then builds each Terrain's chunks for the starting camera (`TerrainCache::prepare`). Before this, the first frame did all of that at once on an empty window. Under the header, the screen shows the project's name, what's being read with "n of m", a progress bar that fills only by that count, with its percentage (no made-up weights between steps; a step with nothing to count, such as reading `world.json`, shows a sliding bar instead, still with Reduce motion), the last five files finished, the seconds taken and Cancel (the current project, or the start screen, stays). The menus are disabled while it loads. A load that finishes within `loading::GRACE` (0.3 s) never shows the screen: until then only the background is drawn. Under the bar a note says why a long load is long: "First open in this version of Axcenity…" while a model is imported because its cooked copy in `.axcenity/imported/models` is missing or from another build (`Assets::model_needs_import`; each engine build imports models again), or "This project was saved by an older Axcenity…" during an upgrade. Meanwhile the viewport's `TextureRenderer` (its pipelines take seconds to make on some cards) is made on a thread (`Viewport::make_renderer_in_background`). Once read, the project opens and the screen stays at least two more frames (only the background after a quick load), then as long as the world's meshes and textures are on their way to the GPU, and until frames come quickly (`loading::Settling`: five in a row within 0.1 s, or twice the quickest frame on a slow computer, so first-use pipelines and ray tracing's acceleration structures are made behind it), up to `FINISHING_LIMIT` (60 s). The viewport's renderer always uploads on its thread (`set_background_uploads`), so turning the camera toward something not on the GPU never stalls a frame: it shows a few frames later. While `Viewport::opening` is set the viewport also asks for every item's mesh, levels of detail and textures, in view or not (`TextureRenderer::preload`), and the screen counts them down ("Sending models and textures to the graphics card", n of m), then says "Getting the editor ready". Paul found the editor slow to answer after the screen went, on Abandoned Farmhouse: only what was in view had been sent. Before this (found on Abandoned Farmhouse), the first editor frame made the renderer and uploaded everything at once, and Windows called the window Not Responding for several seconds. The cover is an `Area` already measured while loading (`finishing_area`), since egui keeps a new `Area` invisible its first frame. A failed open goes to Output and to the start screen's notice. Restoring a version, and tests, still open synchronously (`EditorApp::open`).
- Scripts and physics only run during Play (see `docs/architecture/play-mode.md`).

## Look and feel

- **Category hues** (cohesion pass CP2; `theme::Hue`): the block categories' colours are the editor's one categorical palette, twelve hues (Amber … Slate) with `fill` (white text on it passes AA), `edge` and `ink` (readable as text on the panel, both themes). Blocks take theirs from it (`Category::hue`), and the ribbon tints each group's caption and puts a short bar of its hue under it (`ribbon::group_tinted`, `RibbonGroup::hue`: Game green, Tools and Snapping blue, Build orange, Parts indigo, Lights amber, Effects purple, Gameplay red, Constraints cyan, UI magenta, Scripts violet, Terrain teal, Panels and Overlays slate). Ribbon captions sit on one line across groups: each row is drawn at its own height and then padded down to the tallest row drawn the frame before (a minimum height fed back into Snapping's grid of fields and pushed its caption lower; test `ribbon_captions_share_one_baseline`).
- **Menus** (cohesion pass CP2): every text menu button in a toolbar is `widgets::menu_button`, the same height, corners and look as `widgets::button` (so Model Studio's New and Open line up with Save), opening a submenu inside a menu. Menu items with icons go through `theme::menu_item` / `menu_entry`: the icon in a fixed column (`MENU_ICON_COLUMN`), so every label starts at the same place with an icon or without; Settings > Appearance > **Menu icons** puts the icons at the column's left (default) or centre (`theme::MenuIcons`). The ribbon's tick boxes (Snapping's Move, Rotate, Surfaces, Snap Points, Join Surfaces, Collisions) and its drop-down menus (Overlays, Terrain, Panels, Lighting, View Mode, Constraints, every Insert drop-down, a custom tab's right-click menu) use `theme::menu_item` too (Insert items keep their class colours through `theme::menu_item_tinted`), so the setting reaches them; `theme::with_icon` is only for buttons and headers outside menus.
- **Design system** (`editor-kit`'s `theme.rs` and `widgets.rs`): every colour comes from semantic tokens in `theme::Palette` (app background, panel, surface, elevated, inset, control states, borders, five text levels, accent, success, warning, error), read with `theme::palette(ctx)`; `theme::apply` fills egui's `Visuals` for both themes from the same tokens, so stock egui widgets match. Shape and size have tokens too: `theme::radius` (only three corners: `NONE` for panels, tabs, windows and menus, `CONTROL` 4 for fields, buttons and chips, `CARD` 6 for cards, toasts, popovers and dialogs; `shared_pieces_use_only_the_three_corner_radii` checks the shared pieces), `theme::space` (2, 4, 8, 12, 16, 24) and `theme::size` (icons 13/15/18, row height per density, button height). Node-graph canvases (Material, UI Event Graph, Behavior Tree, Dialogue, the block Graph view and Animation state machines) take `theme::Canvas`, built from the palette: they follow the light theme, select in the accent, and `Canvas::header` darkens a category colour until its white title is AA (tested on every colour). Guides, selection and handles over 3D or UI content use the fixed colours in `theme::overlay` (selection blue, hover gold, magenta snap lines, cyan ruler guides, previews, attachments, handles, warnings, measurements, axes), written nowhere else (tested). Other scene content keeps its own colours (block categories, syntax highlighting, Instance class tints). Shared controls live in `widgets.rs`: buttons by role (primary/secondary/ghost/danger), icon buttons, a segmented control, nav items, section labels, a search field, row hover/selection painting, inspector row names with the changed-value mark (`row_name`, `changed_bar`: a thin accent bar left of a changed row's name, in Properties and the Material tab, with ↺ after the name or at the row's end), ellipsised text, the section chevron and the logo mark image; and (design system V19) `widgets::section` (a folding section with an icon, title and hint, its open state forced, kept by egui's header or remembered under an id across selections, used by Properties and the UI Designer's inspector), `empty_state` (icon, title, a sentence saying how to fill it and an optional button; Properties, Assets, Mixer, Tags and the Model Studio use it) and `chip` (a filter choice, filled when picked; Assets). Graphs open fitted, but never below 80% zoom; a bigger graph opens on its start node, and Frame all still fits all of it.
- **Themes and accent**: neutral, near-monochrome dark (default) and light themes, plus System. One accent (Blue, Violet, Pink, Red, Orange, Yellow, Green or Teal) marks selection, focus rings, the active tab and primary buttons; the rest stays neutral. Text, accent and status colours meet WCAG AA in both themes (checked by a test); the "muted" token is for disabled text, placeholders and decoration only; readable secondary text uses "weak", which is still AA.
- **Menu bar > View and > Viewport** (`app/chrome/menus.rs`): View is the editor's own windows (Panels, Reset Layout, Layout ▸, New Ribbon Tab…). Viewport is what the Scene view draws over the world while editing: Guides (Grid, View Cube, Light Cones, **Ray Tracing Badge**, **Movement Guide**), View Mode ▸, Overlays and Viewport Settings…. The theme left the View menu: it's in Settings, one click away on the gear (and in Ctrl+K as Theme: …).
- **Settings** (`app/settings.rs`, its pages and searchable rows in `app/settings/`; File > Settings…, the gear in the header or on the start screen, Ctrl/Cmd+,): the nav is two groups. **Editor** is the user's own, saved on this computer for every project: Appearance (theme with live previews, accent, interface scale 90–150%), Text & density (Comfortable or Compact, code/Console font size), Editor layout (panels, Reset Layout, presets and saved layouts, new ribbon tab, start screen navigation), **Viewport** (the measuring grid and its strength, view cube, light cones, Show the movement guide, view mode, and the collider/raycast/bounds/emitter/nav mesh/agent path/culling overlays; the same switches as the Viewport menu and the Test tab's View group, one state each), Graphics (this computer's quality preset and shadow quality, shadow distance, post-processing, render scale, texture quality and anti-aliasing overrides, with what's in use and why anything was lowered; applied to the viewport at once and saved as JSON under the `graphics` key; see `docs/rendering/shadows.md`), Shortcuts (every shortcut, from the table below, grouped by where it works), Accessibility (Reduce motion, and **Increase contrast**: design system V18, `Palette::with_contrast`; borders reach 3:1 against the panels, muted text 4.5:1, focus rings are 2 points, and block colours darken until their white labels reach 4.5:1; saved in `appearance` as `increase_contrast`, off for older saves), Updates and Engine. **Project** is one page, **This project**: what's saved in the open project's folder and shared with everyone who opens it (the project's name and folder, then Input…, Collision Groups…, and Workspace and Lighting, which select those objects so their settings show in Properties; Stop first during Play), so a personal preference never lands in a project and the other way round. The Editor layout page also lists the layout presets and saved layouts, each with Use and, for saved ones, Delete. Changes apply at once and are saved as JSON under the `appearance` key; an older save's `theme` key is still read.
- **Density**: Compact tightens spacing and row heights and makes the ribbon icon-only with no captions (names move to tooltips); Comfortable shows icon-over-label buttons with captions.
- **Motion**: micro-interactions take about 160 ms (`theme::MOTION_SECONDS`, egui's `animation_time`): eased hover fills, popups, menus, tooltips and dialogs fading in, sections opening with a turning chevron, a sliding accent underline on ribbon and script tabs, toasts, and a short crossfade when the theme changes. Nothing waits on an animation and the viewport camera is never animated. Reduce motion makes all of it instant and turns off smooth scrolling. Docking changes are not animated (they would animate layout sizes). There is no launch splash: the editor's own start-up is done before its first frame, so a timed one only made up progress (removed on request); a project given on the command line shows the loading screen, which is real. **Entrances** run once something has happened (`theme::arrival`, CSS-style timing curves in `theme::curve`): the start screen's logo mark cuts in diagonally and its name wipes in once per launch; each start page rises 12 points and fades in over 0.34 s; project cards fade in 40 ms apart. The loading screen shows the logo loader (the mark with a band crossing it every 1.3 s, `widgets::paint_mark_sweep`; held still with Reduce motion). Start-screen cards (templates, games and projects) lean toward the pointer as if pressed there, lift on a soft shadow and carry a glare that follows the pointer, while their icon or picture drifts a little further for parallax (`start/tilt.rs`: the card's shapes are tessellated and each vertex projected through a small perspective rotation, about 8° at most; text moves with the surface but stays flat). The start screen's navigation icons glow in the accent on hover (faintly while selected) and float toward the pointer (`widgets::icon_hover`). Reduce motion keeps the glows and drops the tilt, lift and drift; Learn cards keep the older pool of light (`widgets::spotlight`). No animation runs on a timer while idle (no periodic shine, no ambient glow): it would wake the window at uneven intervals, which is the flicker described under Steady frames.
- **Fonts**: Inter (Regular, Medium, SemiBold) for the UI, Plus Jakarta Sans Bold for page and dialog titles and the wordmark (`theme::display_family`, tracked tight), JetBrains Mono for code, the Console and uppercase micro-labels (`widgets::micro`, used by `section_label`), Phosphor for icons, egui's own fonts as fallback. The type scale is in `theme::type_scale`; hierarchy comes mostly from weight and colour. The start screen sits on a backdrop (`start/backdrop.rs`) drawn under the navigation too, so it stays put while the sidebar slides: a wash warming toward the accent at the bottom, a field of faint stars, aurora light in the accent and its two neighbouring hues orbiting slowly, a glow on the horizon with rings rippling out from it, wireframe solids (tetrahedra, cubes, octahedra, icosahedra) turning and drifting in the distance, three layers of ridged hills with accent outlines, a grid floor running to the horizon with lines coming forward, and a soft vignette. The sidebar and top bar are hazy glass over it (`backdrop::glass`, 90% of a tint pushed away from the text colour, with a haze toward the top, a border and a shine line), and each page's content sits on a larger pane of the same glass (`backdrop::reading_glass`), so the scene stays a subtle frame around the text. `text_on_glass_meets_wcag_aa` checks that every text colour reaches 4.5:1 on the glass over the backdrop's brightest and darkest parts, for every accent, both themes and both contrast modes. The backdrop doesn't follow the pointer. Its clock only advances with frames the editor draws (by `stable_dt`, so a pause holds the scene); it never asks for frames itself with a timer, since a timer waking the window is the VRR flicker above (an earlier ~30 Hz atmosphere did). The start screen keeps frames steady instead (see Steady frames). Reduce motion holds it still.
- **Icons**: Phosphor, as an icon font (`egui-phosphor` 0.10), so an icon is a letter inside any text. Every Instance class has an icon and a softened colour (`theme::class_icon`, `class_color`) in the Explorer and tabs; ribbon icons are neutral except Play (success) and Stop (error).
- **Title bar** (`window_frame.rs`, like VS Code): there is one bar. The OS title bar is off and the header is the window's title bar, 34 points tall: logo mark and menus at the left, the window title in the middle (`Name* - Axcenity Editor`, kept clear of the menus), then the Playing badge, Settings and the window buttons. Its empty space drags the window; a double-click maximizes or restores. On Windows and Linux the window has no OS frame, so the editor draws minimize, maximize/restore and close (close turns red on hover and asks about unsaved changes, like File > Quit), 5-point resize grips along the edges and corners, and a one-pixel border; grips and border are off while maximized or fullscreen. On macOS the frame stays, the content runs under a transparent title bar, and the header leaves room at its left for the traffic lights (none in full screen, where macOS hides them); a double-click does what System Settings > Desktop & Dock says (fill or zoom, minimize, or nothing). The OS still gets the title, for the taskbar and window switcher.
- **macOS menu bar** (`app/native_menu.rs`, `app/native_menu/macos.rs`): on macOS the menus are in the system menu bar, not the header, which keeps the logo, the title and the chips. They're built as data each frame (`EditorApp::native_menus`) and turned into an `NSMenu` with `muda`, changed in place while a menu keeps its shape and rebuilt when its items change. The Mac layout: the app menu (About Axcenity, Check for Updates…, Settings… ⌘,, Services, Hide, Hide Others, Show All, Quit ⌘Q, which asks about unsaved changes like File > Quit elsewhere), then File, Edit, View (with Enter Full Screen ⌃⌘F), Viewport, Debug, Window (Minimize, Zoom, Bring All to Front, and the open windows, floating panels too) and Help (with the system's search field). Toggles are check items; the header-only widgets became items: the loading screen's time is Build Game > Show for at Least, deleting a saved layout is View > Layout > Delete Saved Layout. Items show their keys from the shortcut table when they have a modifier or are a function key (plain keys such as Backspace would be taken from text fields). macOS sends those keys to the menu first, so when keys choose an item the editor hands the same keys to egui (`raw_input_hook`) instead of running it, and they act as on Windows and Linux (Cmd+Z in a text field undoes the typing); such items stay enabled, since a disabled item would swallow its keys. In full screen the system shows the menu bar when the pointer reaches the top of the screen. A new header menu item needs its twin in `native_menus`: `every_header_menu_item_is_in_the_macos_menu_bar` checks. Tests draw the header menus on every OS (`window_frame::NATIVE_MENU` is off in tests).
- **Shell**: the header (above), ribbon tabs with an accent underline, the ribbon (`ribbon.rs`) under them, then the dock: quiet tab bars on the app background, the active tab joined to its panel, square corners throughout (tabs, panels, windows and menus), hairline dividers one physical pixel wide at any scale that turn accent when hovered or dragged, and panels at least 140 points wide or tall. The Explorer highlights whole rows with indent guides; Properties shows what's selected, then collapsible sections with aligned name columns; Output has severity filters with counts; Assets has category chips and a search field. Saving and importing confirm with a toast (`toast.rs`) that fades after 2.4 s; warnings and errors stay until closed with their ×, and clicking one opens the Console on that line. At most three show; the rest are counted in an "N more errors in the Console" note. The full message is always in the Console, whose tab adds "⚠ N" in red while it's hidden and errors came in since it last showed (`Output::unseen_errors`). While no Scene View shows (a script or another tab in front of it), the ribbon's scene-only groups (`RibbonGroup::needs_scene`: Tools, Snapping, Parts, Build, Solid, Constraints) are greyed out and their keys do nothing, with **Show Scene** before them to bring it back (`EditorApp::scene_shown`: drawn this frame or the last). Tool windows (Settings, Input, Collision Groups, Version History, Find in Scripts, New Custom Material, References, Learn, the tab editor) are `widgets::tool_window`s: icon and title, no collapse arrow, centred and kept on screen, Escape closes the one on top once no text field has the keyboard. Every dialog is built from `dialog.rs`'s pieces (`modal`, `header`, `buttons`; `ask` for questions): icon tile and title at the top, buttons at the bottom right with the main one last, Enter for the main button (from a text field only when it's the dialog's only input; never a Danger button), Escape or a click outside to cancel. `dialogs_and_tool_windows_are_built_from_the_shared_pieces` keeps new ones on them.
- **Panels at any shape** (v3 Phase 3; `editor-kit`'s `responsive.rs`): every panel keeps its contents inside it when docked tall and narrow. Three shared layouts do it: `toolbar` (controls that wrap onto more rows), `form` (names and controls in a grid whose name column is 38% of the width, 64–150 points; below 280 points each control goes under its name and sliders fill the width) and `split` (two panes side by side, or stacked below a width). Properties, the Style section, the Terrain Studio and the Animation inspectors use `form`; vectors wrap their axes and a UDim2 puts Y under X below 270 points. The Explorer only scrolls vertically: names end in "…" and a row drops its class label when the name would get under 72 points. Assets switches to a list (see `docs/editor/assets.md`). The Animation tab's clip and state machine views stack below 560 points, and its outline folds into the breadcrumb below 720 (see `docs/editor/import.md`); a state machine's live preview goes above its controls below 420 points, and a toolbar starts a new row before a combo box that wouldn't fit (`responsive::room_for`). A second drawing test (`the_animation_tab_says_where_you_are_and_fits_any_shape`) draws the tab with a clip and with a state machine open at 600×400, 260×900 and 1100×600. A drawing test (`every_panel_fits_a_narrow_column_and_a_short_strip`) draws each closable panel at 260×900 and 900×260 and fails if anything is drawn outside it; with `AXCENITY_SNAPSHOTS` it saves `panel-<name>-tall.png` and `-wide.png`.

Character Studio's page opens the Character Studio workspace in place of the start screen (`docs/editor/character-studio.md`). Learn's chapters, the Documentation page and the API Reference's examples: `docs/editor/learn-and-docs.md`. The navigation (`start/nav.rs`, `StartNav`, saved under "start navigation") is either the sidebar, which folds to its icons over about 320 ms (width slides, easing out both ways from wherever it is, `Slide`; the page's content is laid out at the width it will have once the slide ends and moves with the sidebar's edge, so cards change size and columns once, on the click, instead of hopping between column counts every frame (`PageRoom`, test `the_page_slides_with_the_sidebar_instead_of_reflowing`); labels and the open header only appear once the rail is wide enough, so titles aren't clipped mid-slide; the folded header stacks the mark and open button with room so neither is cut off; each icon keeps a tooltip), or a top bar (the pages as tabs, the version, Settings; names drop below 1040 points wide, leaving icons with tooltips). - **Versions and updates** (release system Phase 5): Help > **Version Explorer** opens a dock tab (also in View > Panels; `version_explorer.rs`) with five pages read from the release files built into the editor (`crates/editor/build.rs` embeds `releases/`; it works offline and shows public entries only): Overview (this build, the latest release, changes since then, known issues affecting this version with workarounds), Releases (newest first, with Reconstructed and Never-published badges), Features (search and area filter; a feature's timeline), Issues (search; "this version: fixed / affected (confirmed) / affected by its range / not affected / not investigated") and Compare (two versions; the changes grouped breaking first).
